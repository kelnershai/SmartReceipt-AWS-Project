# SmartReceipt - מערכת חכמה לניהול וניתוח קבלות בענן

## תיאור הפרויקט
פרויקט גמר מעשי בקורס ניהול מערכות ענן.
המערכת מבוססת ארכיטקטורת Serverless מלאה ב-AWS ומאפשרת למשתמשים להעלות תמונות של קבלות דרך ממשק דפדפן סטטי. המערכת קולטת את התמונה, מנתחת אותה באמצעות מודל בינה מלאכותית לחילוץ טקסט (OCR), ומקטלגת את התוצאות באופן אוטומטי בתוך מסד נתונים לצורכי מעקב, היסטוריה וניהול הוצאות.

## ארכיטקטורת המערכת והזרימה (Data Flow)
1. **ממשק משתמש (Frontend)**: דף אינטרנט סטטי המבוסס על HTML5 ו-JavaScript, המוגש ומאוחסן בצורה חסכונית באמצעות **Amazon S3 Static Website Hosting**.
2. **ניהול תקשורת ו-API**: בקשות ה-HTTP מהדפדפן (מסוג POST) מנוהלות ומאובטחות על ידי שער ה-**Amazon API Gateway** (בתצורת HTTP API) עם הגדרות CORS פתוחות.
3. **לוגיקה עסקית ומחשוב**: פונקציית **AWS Lambda** (המריצה סביבת Python 3.12) מתעוררת בצורה סקילבילית, מקבלת את התמונה בפורמט Base64, ומפענחת אותה בזיכרון.
4. **ניהול אחסון (Storage)**: התמונה המקורית נשמרת כגיבוי ב-S3 Bucket מאובטח וסגור לגישה ציבורית.
5. **בינה מלאכותית (AI & ML)**: פונקציית ה-Lambda מעבירה את קובץ ה-Bytes של התמונה ישירות לניתוח בשירות הראייה הממוחשבת **Amazon Rekognition** לחילוץ שורות הטקסט והנתונים המספריים מהקבלה.
6. **בסיס נתונים (Database)**: המזהה הייחודי של הקבלה (UUID), זמן ההעלאה, הטקסט המלא שחולץ והקישור לקובץ נשמרים בטבלת **Amazon DynamoDB** (מסוג NoSQL).

## שירותי AWS שנבחרו לפרויקט
* **Amazon S3**: משמש בשני רכיבים נפרדים: אחד לאחסון הקבלות הגולמיות (פרטי) ואחד לאחסון והגשת קובצי האתר (ציבורי).
* **AWS Lambda**: הרצת קוד ה-Backend ללא שרתים, המבצעת את קבלת המידע, הקישור ל-AI והשמירה בבסיס הנתונים.
* **Amazon API Gateway**: ניהול ה-Endpoints והנתיב המאובטח `/upload`.
* **Amazon DynamoDB**: מסד נתונים מהיר, גמיש ובעל Latency נמוך לשמירת המטא-דאטה של הקבלות.
* **AWS IAM**: ניהול הרשאות קפדני (Roles & Policies) המאפשר ל-Lambda גישה מוגדרת ל-S3, DynamoDB ו-Rekognition.
* **Amazon Rekognition**: שירות ה-AI הנבחר (שירות הבחירה של הפרויקט) לביצוע משימת ה-OCR וחילוץ הטקסט.

## אתגרים ארכיטקטוניים ופתרונם במהלך הפרויקט
* **פסק זמן בעיבוד (Lambda Timeout)**: ברירת המחדל של Lambda (כ-3 שניות) גרמה לחיתוך הריצה בעת עיבוד תמונות כבדות. הבעיה נפתרה על ידי הגדלת ה-Timeout ל-30 שניות והרחבת הזיכרון ל-512MB.
